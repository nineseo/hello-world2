# Свой сервер и Claude Code на нём: как это устроить

## 1. Короткий вывод

Ваша схема (поставить Claude Code на сервер и дать ему задания) рабочая, но её нужно поправить в трёх местах:

1. **Не запускайте Claude Code от root.** Агент с правами root на боевом сервере может по ошибке удалить или сломать всё. Root нужен один раз для первичной настройки, её делает готовый скрипт `server/bootstrap-server.sh`, который вы читаете и запускаете сами.
2. **Домен не «добавляют пользователю».** Домен задаётся в DNS на Internet.bs (записи указывают на IP сервера), а сайт принимает веб-сервер Caddy внутри Docker. Linux-пользователь vuli просто запускает приложение.
3. **Разделите разработку и боевой сервер.** Лучше всего два сервера: маленький для разработки (где живёт Claude Code) и боевой (только запуск сайта, выкладка автоматическая). Если один сервер, соблюдайте правила безопасности ниже.

## 2. Две схемы

| | Схема А (рекомендую) | Схема Б (ваш план) |
|---|---|---|
| Где пишется код | Облачные сессии Claude Code на claude.ai/code или Claude Code на вашем компьютере | Claude Code на сервере |
| Где работает сайт | Сервер, выкладка автоматическая (GitHub Actions) | Тот же сервер |
| Плюсы | Ошибка агента не ломает боевой сервер; на сервере нет входа в Claude | Всё в одном месте, быстро |
| Минусы | Нужен GitHub; больше настройки выкладки | Агент рядом с боевыми данными; нужны строгие правила; на сервере хранится вход в Claude |

Можно начать со схемы Б на отдельном **стенде** (тестовом сервере), а боевой сервер запустить позже по схеме А.

## 3. Как передать Claude Code всё, что мы делали

История этого чата в новую сессию **не переносится**. Она переносится файлами:
- `docs/` (решения, бриф, курс, выводы по конкурентам, домены и знаки) в репозитории hello-world2;
- `prototype/` (дизайн и логика уроков 1–2);
- `CLAUDE.md` в новом репозитории: Claude Code читает его автоматически при старте и знает правила проекта;
- `docs/10-tasks.md`: список задач по порядку с критериями «готово».

Шаблон `CLAUDE.md` для нового репозитория лежит в `templates/vuli-repo/CLAUDE.md`. Скопируйте его в корень `vuli` под именем `CLAUDE.md`.

Правило работы: после каждой задачи Claude Code обновляет `docs/02-decisions.md` и отмечает задачу в `docs/10-tasks.md`, потом делает коммит. Так ничего не теряется между сессиями.

## 4. Пошагово (схема Б на стенде)

**Шаг 1. Ключ на вашем компьютере.** В терминале: `ssh-keygen -t ed25519 -C "vuli"`. Файл `~/.ssh/id_ed25519.pub` это публичный ключ (его можно показывать), файл без `.pub` секретный (не отправлять никому).

**Шаг 2. Сервер.** Закажите VPS: Ubuntu 24.04 LTS, 2 ядра, 4 ГБ памяти, 40 ГБ диска. Если провайдер просит ключ при создании, вставьте публичный ключ.

**Шаг 3. Первичная настройка (один раз от root).**
1. Подключитесь: `ssh root@IP-сервера`.
2. Скачайте скрипт из репозитория `server/bootstrap-server.sh`, **прочитайте** его и запустите: `bash bootstrap-server.sh`. Он спросит публичный ключ.
3. Не закрывайте root-консоль. Во втором окне проверьте: `ssh vuli@IP-сервера`. Если вход работает, закрывайте root.

**Шаг 4. DNS на Internet.bs.** Добавьте A-запись: `staging` → IP сервера. Позже `@` и `www`. Подождите до часа, пока обновится.

**Шаг 5. Доступ сервера к GitHub.** Под пользователем vuli: `ssh-keygen -t ed25519` (ключ сервера). В каждом репозитории (hello-world2 и vuli) GitHub → Settings → Deploy keys → добавьте публичный ключ (для vuli с правом записи, для hello-world2 только чтение).

**Шаг 6. Репозитории на сервере.**
```
git clone -b claude/wonderful-einstein-6a6c4s git@github.com:nineseo/hello-world2.git ~/vuli-docs
git clone git@github.com:nineseo/vuli.git ~/vuli
```
Скопируйте `~/vuli-docs/templates/vuli-repo/CLAUDE.md` в `~/vuli/CLAUDE.md` и закоммитьте.

**Шаг 7. Claude Code.** Установите по официальной инструкции (code.claude.com/docs), под пользователем vuli. Вход в аккаунт выполняется по ссылке, которую вы откроете на своём компьютере. Запускайте внутри `tmux` (чтобы не прерывалось при потере связи): `tmux new -s vuli`, затем `cd ~/vuli && claude`.

**Шаг 8. Первое сообщение.**
```
Прочитай CLAUDE.md и docs/00-start-here.md, docs/02-decisions.md, docs/07-site-build-brief.md, docs/10-tasks.md в ~/vuli-docs и ~/vuli. Выполняй задачи из docs/10-tasks.md по порядку, начиная с T01. После каждой задачи обнови docs/02-decisions.md, отметь её в docs/10-tasks.md и сделай коммит. Я не программист: объясняй простыми словами. Перед установкой пакетов и запуском команд, которые меняют сервер, объясняй, что и зачем. Не проси вставлять пароли в чат.
```

## 5. Правила безопасности (обязательно)

- Claude Code работает **не от root**, в режиме с запросами разрешений. Не включайте режим «пропустить все разрешения» на сервере с данными.
- Перед крупным заданием сделайте снимок диска у провайдера (snapshot).
- Секреты (пароль БД, ключи Resend) лежат в `.env` на сервере с правами `chmod 600` и не попадают в Git. Не вставляйте их в чат.
- Группа docker у пользователя даёт почти права root: поэтому на боевом сервере с реальными данными лучше схема А.
- Вход в Claude на сервере хранится на диске: если сервер взломан, отзовите сессию в аккаунте Claude.
- Двухфакторная защита: GitHub, регистратор, аккаунт хостинга, Claude.
- Ежедневные копии базы данных вне сервера (одна из первых задач).
- На сервере запрещены вход root и вход по паролю (делает скрипт); следите за обновлениями.

## 6. Что я не проверял
Скрипт `server/bootstrap-server.sh` не запускался на реальном сервере (проверен только синтаксис). Команды установки Claude Code и ограничения облачных сессий сверяйте с официальной документацией: они меняются.
