# Настройка сервера силами Claude Code (вариант без скрипта)

Решение владельца: сервер настраивает Claude Code с root-доступом, а не скрипт. Скрипт `server/bootstrap-server.sh` остаётся запасным вариантом и справочником.

## Как это безопасно сделать на пустом сервере
1. Сервер свежий и пустой, на нём пока нечего терять. Перед началом сделайте **снимок диска** у провайдера.
2. Запомните, как попасть в **консоль провайдера** (VNC/рескью): если Claude Code ошибётся в настройке SSH или фаервола, вы всё равно войдёте.
3. Войдите на сервер под root, установите Claude Code по официальной инструкции (code.claude.com/docs) и запустите его в `tmux`: `tmux new -s setup`, затем `claude`. Режим с запросами разрешений **не отключайте**: каждую команду вы подтверждаете.
4. Вставьте задание ниже. После настройки root-сессию закройте, дальше работайте под пользователем `vuli`.

## Задание для Claude Code (вставить как первое сообщение)
```
Ты настраиваешь новый пустой сервер (Ubuntu 24.04) для сайта vulilang.com. Владелец не программист: объясняй простыми словами, что делаешь и зачем, и спрашивай подтверждение перед рискованными шагами. Не отключай и не обходи защиту; все изменения записывай в /root/server-changelog.md.

Сделай:
1. Обнови систему. Включи автоматические обновления безопасности.
2. Создай пользователя vuli (вход по SSH-ключу; спроси у меня публичный ключ), добавь в группы sudo и docker. Спроси, разрешить ли vuli sudo без пароля (рекомендуется для этого стенда).
3. SSH: спроси режим: (1) без root и без паролей; (2) root только по ключу; (3) root и пароли разрешены (выбор владельца допустим, но предупреди о рисках и убедись, что пароль root длинный). Перед перезагрузкой sshd запусти sshd -t и проверь, что я могу войти в НОВОМ окне, а старое не закрывай, пока проверка не пройдена.
4. Фаервол ufw: открыть только 22, 80, 443. Не включай его, пока SSH-порт точно разрешён.
5. Установи fail2ban, Docker и Docker Compose, git, tmux, curl, unzip.
6. Создай /srv/git, владелец vuli. Затем под пользователем vuli: git init --bare /srv/git/vuli.git; git clone /srv/git/vuli.git ~/vuli.
7. Загруженный мной архив vuli-handoff.zip (лежит в /root) распакуй в ~vuli/vuli-docs, владелец vuli. Скопируй templates/vuli-repo/CLAUDE.md в ~vuli/vuli/CLAUDE.md и сделай первый коммит.
8. Установи Claude Code для пользователя vuli (по официальной инструкции) и объясни мне, как войти в аккаунт и запустить его в tmux.
9. Напиши, какую запись A добавить в DNS на Internet.bs (staging -> IP этого сервера) и как проверить, что она сработала.
10. В конце дай мне итоговый список: что установлено, какие порты открыты, как зайти под vuli, как войти через консоль провайдера, и какие шаги ещё остались.

Не ставь ничего лишнего и не меняй пароль root без моей просьбы.
```

## Что делать, если позже нужны права root
- Рекомендую режим «vuli с sudo без пароля»: Claude Code сам выполнит `sudo ...`, а вы подтвердите команду в запросе разрешения. Заходить под root не придётся.
- Если вы выбрали вход root по паролю (режим 3), можно зайти и под root, это ваш запасной вариант. Минусы описаны в `docs/09`.
- Всегда есть консоль провайдера как последний запасной вход.
